Wire v6.5 (dual speed) — CHANGES
================================

База: Wire v6.4.1. Версия 6.5 = полезное из ПЕРЕРАБОТАННОЙ пользователем
версии (upload/Wire_dual_speed.zip, база v6.1 + правки «6.2/6.3»), слитое
поверх v6.4.1. LCD-библиотека: LiquidCrystal_I2C v1.2.2-alecs (см. её
CHANGES.txt, «ДОПОЛНЕНИЕ 2/3»).

ПРИНЯТО из переработки (проверено ревью и хост-стендом):
- twi_recover() — публичное восстановление залипшей шины: до 9 тактов SCL,
  пока слэйв не отпустит SDA, затем STOP (только при свободном SCL);
  ожидание отпускания SCL при clock stretching (до ~50 мкс); возвращает 1,
  если обе линии свободны. Фиксы v6.4.1 сохранены (TWCR=0 до бит-бэнга,
  чтение TWI_PIN, а не PORT-латча).
- TWI_AUTO_RECOVER=1 (по умолчанию): при ЛЮБОМ таймауте транзакции
  twi_reset() вызывает twi_recover() автоматически — шина освобождается
  без участия скетча (~100 мкс на сбой). -DTWI_AUTO_RECOVER=0 — старое
  поведение (просто рестарт модуля). Полупериод тактов —
  TWI_RECOVER_HALF_US (5 мкс -> ~100 кГц).
- Wire.recover() + макрос WIRE_HAS_RECOVER: ручное восстановление из
  скетча (сбрасывает tx-состояние, возвращает код twi_recover()).
- twi_setClock(0) ВОЗВРАЩАЕТ авто-режим скорости (раньше — только
  end()+begin()). setClock(f != 0) по-прежнему выключает авто-режим:
  ВСЯ шина, включая PCF8574, поедет на f (выше 100 кГц для PCF8574
  не гарантировано).
- ЛЕНИВЫЙ setClock: ручное значение хранится в twi_manual_twbr и
  применяется в twi_pick_speed() перед очередным START. Запись TWBR
  посреди удержанной шины (rep-start) стала невозможной by design —
  проверка twi_inRepStart в setClock больше не нужна.
- twi_init(): всегда настраивает пины/TWSR; TWBR = manual ? manual_twbr :
  TWI_TWBR (прежний пропуск блока при manual-латче был хрупче).
- TWI_TWBR_FOR: добавлен ВЕРХНИЙ кламп 255 (TWI_TWBR_RAW/TWI_TWBR_CLAMP):
  при очень малых f раньше было тихое переполнение uint8_t. Проверяется
  compile-time static_assert в тестах. TWI_TWBR по умолчанию теперь
  TWI_TWBR_FOR(400000UL) — от F_CPU (8/16/20 МГц).
- twi_recover/twi_stop не используют util/delay.h — только
  delayMicroseconds() из Arduino.h; twi_stop поллит TWSTO без пауз,
  проверяя таймер раз в 256 итераций (как twi_wait).

ОТКЛОНЕНО из переработки (осталась семантика v6.4.1):
- Широкая маска TWI_ADDR_IS_SLOW (вся линейка PCF8574 0x20-0x27/0x38-0x3F):
  v6.4 сознательно сузил до 0x27/0x3F — MCP23017 (0x20-0x26), AHT10/20
  (0x38), SSD1306 (0x3C/3D) не должны молча замедляться до 100 кГц.
  Формула-маска для всей линейки добавлена в комментарий twi.h как готовый
  пример переопределения.
- Снятие guard'ов writeBuf (length/address/data) и #ifndef
  WIRE_BUFFER_LENGTH.
- Снятие WIRE_HAS_TIMEOUT и no-op-стабов timeout-API (совместимость со
  сторонними библиотеками).
- Код 5 при STOP-таймауте в writeTo: остался код 6 (диагностичнее,
  задокументирован в README, покрыт тестами); guard-коды 4 — остались.

Исправления v6.4.1 (ревью пользовательской v6.4) — всё ещё в силе:
1. BUG (twi_reset): recover при TWEN=1 — бит-бэнг не доходил до шины
   (исправлено: TWCR=0 до recover; в v6.5 то же в twi_recover()).
2. BUG (twi_recover): SDA читался из PORT-латча — 9 тактов не
   генерировались (исправлено: TWI_PIN).
3. BUG (twi_disable): не сбрасывал латч manual (исправлено).

Тесты (хост-стенд: моки avr/io.h, compat/twi.h, Arduino.h со счётчиком
delayMicroseconds; micros-тик 1000 мкс):
- юнит AUTO: ленивая setClock-математика (100k->72 ... 31k->250) через
  транзакцию, setClock(0) -> авто, латч manual переживает init,
  disable+init сброс, узкая маска 12 адресов, guard'ы ==4, код 6,
  twi_recover(): свободная шина = 3 полутакта (вернёт 1), застрявший SDA
  = 21 (9 тактов + STOP, вернёт 0), застрявший SDA+SCL = 469 (STOP
  пропущен) — PASSED;
- юнит MANUAL — PASSED;
- 8 МГц: FAST=10/222 кГц, SLOW=32/100 кГц, кламп 31 кГц -> 121,
  static_assert верхнего клампа — PASSED;
- интеграция LCD v1.2.2-alecs + Wire v6.5: begin() на битой шине false,
  TWBR по адресу, ленивый setClock, setClock(0), recover(), guard'ы,
  переполнения буфера — PASSED; -Wall -Wextra чисто.
